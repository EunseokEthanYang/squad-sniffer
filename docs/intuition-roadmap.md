# 직관성 향상 로드맵 & 실시간 데이터 요구사항

## A. 더 높은 직관성을 위해 필요한 작업 (우선순위순)

| # | 작업 | 왜 (원리) | 상태 |
|---|---|---|---|
| 1 | **사건을 사물로**: 검증 ✗ 도장, 손들기 ✋, 문 열림, 카드 이동 — 텍스트 없이 사건이 보이게 | 뮤트 테스트 / Heider-Simmel(움직임이 서사를 만든다) | ✅ 구현 (director) |
| 2 | **판정 공식 카드**: 에스컬레이션·손절 순간 "이득 14% < 기준 25% → 손절" 고정 | 은유가 메시지를 잡아먹지 않게 숫자 목줄 | ✅ 구현 |
| 3 | **미터기 = 서술어**: 모든 비용 사건이 미터기 변화와 동시에 보임 | 게임은 주어, 미터기는 서술어 | ✅ (단가 램프·가중 토큰) |
| 4 | **빈 자리·공석 교탁의 정적 드라마** ("일어나지 않은 일" 보여주기) | 스크립트 위반 = 주목 | ✅ (cascade 테마) · 빈 책상 유령 라벨은 옵션 |
| 5 | **정보 없는 시간 제거**: 이벤트 없으면 자동 빨리감기, 이벤트 순간 슬로우/줌 | 정보 밀도 | ⬜ 미구현 — director에 속도 배율·카메라 줌 추가 |
| 6 | **내 문제 추적(참여 동사 "넣는다/따라간다")**: 내가 낸 문제 카드에 내 문구가 달리고, 카드 클릭 시 그 문제의 타임라인 | 택배조회 효과 | ⬜ 카드에 task.text 표시는 됨 / 클릭 타임라인 미구현 |
| 7 | **"당신이 심판" 모드**: 불일치 순간 일시정지 → 심사위원이 호출/손절 선택 → 시스템 판정과 비교 | 이해의 최상급은 결정 | ⬜ 미구현 (director budget 이벤트에 interactive 옵션) |
| 8 | **관제 뷰(노선도) 2안**: 같은 이벤트를 먹는 두 번째 렌더러 — 흐름 가시성·정직성 최상 (심사 만장일치) | 공통 경험 다이어그램 | ⬜ 미구현 (engine/subway.js 추가만으로 가능) |
| 9 | **30초 뮤트 테스트 실측**: CS 비전공자 2~3명, "방금 무슨 일?" / "뭐 만져보고 싶어?" | 시뮬레이션 대신 측정 | ⬜ 팀 실행 |
| 10 | 캐릭터 역할별 고유 도트(같은 로봇 색만 다름 → 형태 차이) | 식별성 | ⬜ 팀 아트 |

## B. 실시간으로 와야 하는 데이터/파일 — 명명백백 정리

### B-1. 페이지가 로드하는 파일 (정적, 실시간 아님)
`index.html`, `css/game.css`, `js/**`, `backend/aigo_client.js`, `backend/aigo_state.js`, `assets/sprites_data.js`(1.4MB, 생성물). 이것들은 배포 시 한 번만 올라가면 된다.

### B-2. 실시간(스트리밍)으로 와야 하는 것 — 없으면 "살아 움직이는" 시각화가 안 됨
| 데이터 | 경로 | 주기/방식 | 화면의 무엇이 움직이나 |
|---|---|---|---|
| **SSE 이벤트 스트림** | `GET /api/v1/events` (프록시 `/aigo/api/v1/events`) | 푸시(실시간) | 핸드오프·검증·판정·제출 연출의 1차 소스. **이벤트 이름·페이로드는 첫 실행 때 확정** (`sse_tap.py` 기록 중) |
| **에이전트별 토큰 사용량** | `GET /squads/{id}/budget/usage` → `perAgentTokens` | 2초 폴링 (fastMs) | 미터기 증가, 누가 지금 일하는지(토큰 증가 = working 애니) |
| **활동 로그 증분** | `GET /squads/{id}/activity-log/load` | 10초 폴링 | 말풍선(say), "왜"의 문장 |
| **현재 실행 상태** | `GET /squads/{id}/executions/{eid}` | 2초 폴링 | 문제 시작/종료(칠판·제출) |
| 추론 속도 | `GET /monitoring/metrics.inference.tokensPerSecond` | 2초 폴링 | HUD 속도감(보조) |

### B-3. 준실시간/정적 (시작 시 + 10초 폴링이면 충분)
`squads/{id}`(에이전트 목록·모델·역할) · `readiness` · `budget`(한도·경고선) · `tasks`, `tasks/graph`(waves) · `history`(사후 리플레이용) · `router/status`(모델 3종) · `analytics`.

### B-4. 스쿼드 쪽에서 **남겨줘야** 시각화가 정확해지는 것 (요청 사항)
검증 결과·에스컬레이션 이유·예산 판정 숫자·제출 정오 — 5종 구조화 로그(`data-catalog.md` 4절). 서버 로그나 activity-log 메시지에 JSON 한 줄로만 남겨주면 `config.eventMap` / `live.js`가 그대로 먹는다. 이게 없으면 "누가·얼마나·언제"는 정확, "왜"는 추정.

### B-5. 쓰기(선택, 팀 승인 필요)
문제 내기 → `POST /squads/{id}/execute` · 말 걸기 → `POST /squads/{id}/agents/{aid}/message` (실제 토큰 소모 → 데모용 스쿼드 분리 권장)
